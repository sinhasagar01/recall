function merge(intervals: number[][]) { // sort by start const sorted = [...intervals].sort((a, b) => a[0] - b[0]); const out: number[][] = []; for (const [start, end] of sorted) { const last = out[out.length - 1]; if (last && start <= last[1]) last[1] = Math.max(last[1], end); else out.push([start, end]); } return out; }
follow-up after the code That works. What is the complexity, and where does it come from? Then: if the input arrives already sorted, can you do better — and what would you need guaranteed?

Phased, not counted

Sixty minutes of design is four movements, not eleven questions. The phase strip is the progress — there are no pips, because a pip per question would count a shape that has no questions. Advancing is either yours (Move to scale) or the interviewer's when a phase is done; the minute ranges are a guide the clock does not enforce, exactly as the advisory clock does not end a round.

With ADRs in your ledger the tag reads drawn from ADR-002 and the round asks you to defend a decision you actually made. With an empty ledger it draws design-shaped topics instead and says so — the round still runs, on weaker material, and the tag does not claim a source it does not have.

The scorecard, for both
Unchanged, with two additions. A DSA round's question by question rows are problems, and each carries the code you wrote, collapsed, expandable. A design round's rows are the four phases. Everything else — the four dimensions, the offer step, the sparkline — is exactly as it is for a concept round.

The offer step still offers topics. A DSA problem is not a topic in your library, so a problem you fumbled offers nothing to mark weak — and the row says so, in the same words an unattributable question already uses.

The rules

This file draws only what this arc builds: two round types added to the five that ship. Everything else on every screen is unchanged and is specified by interview-reference.html.

DSA
  • CodeMirror 6, and nothing smarter than a whiteboardNo autocomplete, no type checking, no linting. An interview editor that helps you is not testing you.
  • Nothing is executedNo runner, no test harness, no sandbox. The model reads the code as text.
  • Problems are generated, not drawn from your libraryThe only round type that is. Say so on the card: your library has no DSA problems in it, and pretending otherwise would be the fake this product refuses. The pool line reads N problems · your code is kept.
  • Your code persists; the conversation does notA new column, and the session-one hasnt_column('code') assertion is marked SESSION ONE ONLY — removing it is part of this arc's work, not a regression in it.
  • The follow-up is the point, as everWorking code is the start. Complexity, where it comes from, and what breaks is where the round is.
System design
  • Four phases at every lengthThe phases stretch; the count does not. Twenty minutes is a rushed design round, not a two-phase one.
  • Phased, not countedNo pips. A pip per question counts a shape with no questions.
  • Forward onlyA design round is a conversation and you cannot un-say the requirements.
  • ADRs first, topics as a fallback, and it says whichWith ledger ADRs it asks you to defend a decision you made. Without them it draws design-shaped topics and the tag does not claim a source it does not have.
Both
  • Every other rule is inheritedInterviewer level is a prompt not a multiplier; clarifying questions count for you; three hints; the advisory clock; End the round always works; the round is never resumed; the scorecard offers and never writes.
  • The scorecard changes only its rowsProblems for DSA, phases for design. Four dimensions, the offer step, the sparkline: unchanged.
  • A problem offers nothing to mark weakIt is not a topic in your library, and the row says so rather than omitting itself.
Not built
  • No execution of any kindNot now, not stubbed, not behind a flag.
  • No machine coding roundA build you did elsewhere is a ledger item with a repo link and a deployed URL — that decision stands.
  • No diagram toolA design round is spoken and typed. A canvas is a different product.
