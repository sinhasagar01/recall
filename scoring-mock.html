The rules

  • Render what is already knownThe stat strip is counted in code — answered, follow-ups held, questions asked, hints, elapsed. None of it waits on a model, so none of it waits on screen.
  • The skeleton is the real geometrySame hero, same strip, same four cards, same question rows in their real order with their real titles. When the score arrives it fills the shape rather than replacing a different one, so nothing jumps.
  • Indeterminate, never fake progressA shimmer and a pulsing meter, because it is one round trip and there are no stages. A bar that fills to 80% and waits is a lie about a request that either returns or does not.
  • No buttons while it worksAn escape hatch on a screen you are meant to wait on reads as "this may not finish". The browser's back button has always been there for anyone who truly wants out.
  • After twenty seconds, one sentence and one way outThe wait has become unusual, so say so and offer the exit. It says leaving loses the score, because it does.
  • On failure, the buttons returnSame two controls, opposite meaning — there is now nothing else to do. And the error names the real reason, with an explicit line that nothing was written.
  • Reduced motion stops every animationThe shimmer, the meter and the dots all obey it, and the screen still reads correctly still.

The old screen's defect was not that it lacked a spinner. It was that it showed nothing it already knew, invented an escape from a working process, and left the reader unable to tell waiting from broken.
