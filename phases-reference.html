The rules

Every decision this reference encodes. Where this page and the screens disagree, the screens win.

Data
  • Two new tables: phases and capabilitiesA phase has a name, an optional free-text “when”, and an optional sources line. A capability has a name and belongs to a phase. Plus a nullable capability_id on topics.
  • A topic serves at most one capabilityThe column, not a join table — the same shape as source_id. If a topic genuinely serves two, the capability is written too broadly and should be split.
  • Deleting a phase deletes its capabilities and keeps every topicon delete cascade from phase to capability, on delete set null from capability to topic. The confirmation names both.
  • capability_id is omitted from the domain TopicThe load-bearing kind of omission, exactly like source_id: it is what lets the boundary test forbid every capability column in a queue module with no exception.
Demonstrated
  • Two halves, both requiredSomething linked is at okay or better on recall, AND something linked carries rebuild, challenge or production evidence. Your own rule: recall evidence plus a rebuild, challenge or capstone decision.
  • The box has no click handlerThere is no manual tick anywhere on this screen. A course ending changes nothing, and neither does your opinion of yourself on a good day.
  • An undemonstrated capability says which half is missing“You can say it, but you have not built with it” and “You have built with it, but you cannot say it cold” are opposite instructions, and a bare unchecked box gives neither.
Behaviour
  • Add a phase when you reach itNo seeded curriculum, no import, no template. Six phases typed on day one is a plan, and a plan belongs in a document.
  • A phase is current when it is the earliest not fully demonstrated — addedThe page marks one phase “Current” and this list never said how it got there, which is the gap that produced the question. It is derived: the earliest phase with a capability still undemonstrated. No stored flag, no date, and a phase with no capabilities counts as unfinished. It changes when evidence changes and at no other time — if every phase is fully demonstrated, none is current, and that state is drawn.
  • “When” is free text, never a dateA date would let the product tell you that you are behind. It is not going to do that.
  • No percentage, no burn-down, no week counter“2 of 4” is a count you can click through to. Nothing on this screen changes because a date passed.
  • Mobile joins the library head clusterBeside Sources and Settings. Rule 13 intact, tab bar unchanged.
  • Crimson marks weak confidence and nothing else — correctedAn earlier draft of this page coloured every missing half in --flag. DESIGN.md allows that colour only for weak confidence, a destructive action or an error, and arc 2 already narrowed it once. “at weak” and “all weak or new” keep it because they are weak confidence; “no rebuild, challenge or production” and “nothing linked” are absences, and an absence is not an error. They render as ordinary meta. The why-line already names the missing half in words, so nothing is lost but the alarm.
Not built
  • No AI in this arcNothing generated, nothing suggested. Arc 6 attaches elsewhere; leave nothing stubbed here.
  • Capabilities never reach the queueA capability has no confidence, is never practised, and never appears in practice selection or on the weak page. Asserted the way arcs 1 and 2 assert their boundaries.
  • No course list, no completion trackingThe sources line on a phase is free text. Ticking a course is the thing this whole screen exists to refuse.
  • No ledger, no TodaySeparate arcs. Scheduling, dashboards, analytics and gamification stay excluded.
